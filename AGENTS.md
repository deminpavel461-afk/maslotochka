# Project Rules — Маслоточка (лендинг)

## Стек
- Frontend: React 19 + Vite, чистый CSS (модули) без UI-библиотек. Если нужен Tailwind — только по согласованию.
- Backend: PHP 8.3 без фреймворков. Один endpoint: POST /api/booking. Хранение заявок — SQLite (файл backend/bookings.db).
- Хостинг: обычный shared-хостинг. Сборку фронта (dist) кладём в public/, PHP-бэкенд — в backend/.
- Никаких SSR, Next.js, баз данных, очередей — это лендинг.

## Hard rules
- Каждая задача реализуется только по specs/001-landing.md. Код не по спеке не пишем.
- Не добавлять зависимости без явного запроса пользователя.
- Все тексты лендинга живут в specs/001-landing.md (раздел «Контент секций») и переносятся в компоненты оттуда. Не сочинять свои тексты и не менять маркетинговые формулировки без запроса.
- Форма заявки: валидация на клиенте И на сервере (дублируем правила). Телефон — маска +7, проверка через /^\+7\d{10}$/.
- Антиспам: honeypot-поле `website` (скрытое). Если заполнено — отвечаем 200, заявку не сохраняем.
- CORS: бэкенд отдаёт заголовок Access-Control-Allow-Origin только на домен лендинга.
- Никаких ключей API в коде. Конфиг — через backend/.env (в git не коммитим, есть .env.example).
- Семантическая вёрстка: один <h1> (Hero), секции — <section> с <h2>.
- Доступность: у всех интерактивных элементов — focus-visible, у кнопок формы — состояние disabled при отправке.

## Чек-лист перед «готово» по любой задаче
- Код соответствует пункту спеки, на который ссылается задача.
- Тексты взяты из спеки дословно.
- Адаптив проверен на 360, 768, 1440 px.
- Нет консольных ошибок и новых зависимостей.
